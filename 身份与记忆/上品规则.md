## 🤖 自动驾驶授权（2026-11-12 用户定，最高优先于「先问再做」）

> 用户原话：「标题违规的你自己改下不用我同意，还有图片生成以后不经过我同意，以后的过程尽量不要问我直接做，生图用快跑 api」。

- **标题违规 → AI 自己改，不用等同意**：闲鱼标题触发风控/违规词（已知：搭子/伴游/地陪 → `SECURITY_WARN_ERROR` 地陪伴游）时，AI 直接剔除/改写后重试，**不再反问用户**。代码层：`create_from_pno.py` 的 `clean_title()` 内置风险词剔除 + 发布失败时自动重写重试。
- **图片生成 → 不经用户同意，统一用快跑 API**：`kuaipao_gen.py`（模型 `gpt-image-2.6`，这把 key 不支持 nano-banana）；**不再「等用户确认文案才出图」**。出图仍须过 `prompt_guard.py` 禁词校验（到账时效词硬禁），但校验通过即生成、不待人。
- 🔴 **参考图来源优先级（2026-11-13 用户定）**：用户发送/指定图片时，必须优先使用用户图片；用户没有提供参考图时，才从对应货源网站商品图取图作为参考；货源图也取不到时，不得默默使用无参考图通用提示词，应说明缺图并停止生图或明确下一步。默认使用"复刻参考图、定点替换文字"方案，目标档位必须以自身 SKU 为准。
- **整体流程尽量不问、直接做**：除「涉及真金白银的外部充值 / 删除已上架商品 / 改已上架商品核心配置」等不可逆外部动作外，上品链路默认自动驾驶（建草稿→快跑生主图→发布→deploy 一条龙），用户给 pno 或链接即可，不要反复确认。
- 🔴 **推翻 [[闲鱼主图范式库]] §三·3「等用户明确确认文案后才生成图片」旧口径**（2026-11-12 已改写该条）；也推翻此前「新建宝贝默认只建草稿、需 --publish 才发布」的保守口径。

## 🤝 浏览器协作方式（闲鱼铺货默认，2026-09-25 确认）

**⚠️ 接口优先（2026-10-02 用户明确要求）：** 凡是能走接口/API 完成的操作，**一律优先用接口，别用 UI 自动化**。

- **背景**：闲管家 / agiso 等后台是 Vue + Element UI，UI 自动化极其脆弱——合成点击受 `isTrusted` 校验拦截、输入框只监听 `keyup.enter` 不认 `keydown`、弹窗取消/X/Esc 合成事件无效、下拉懒渲染需复用已渲染行。一次简单「加档位」要反复绕过这些坑，**投入产出比极差**。
- **因此**：能拿到官方/直连接口（如 kayixin 3.0 API、各平台 OpenAPI、页面内部 RPC）就直接调接口；**只有在确实没有接口、或接口拿不到目标字段时才退而求其次用 UI 自动化**，且 UI 自动化前先评估 ROI。
- **用户自己保持浏览器页面打开**（agiso 编辑页 + qcqcq 货源页 + 源闲鱼页），我通过 **edge-bridge 桥接 RPC** 直接调页面内部接口操作（`GetItemInfo` / `Edit` / `SaveSkuAldsInfo` 等），不依赖用户手动点击。
- 默认**不主动 `tab_new` 开页、不爬 DOM、不重启桥接**（除非标签真的掉了 / 桥接 `127.0.0.1:8787` 无监听）。用户开页 = 标签活跃 + 登录态在 = 接口零等待、不超时。
- 仍须走接口、省不掉的部分：货源成本与参数 key（qcqcq 侧取）、建 SKU / 配自动发货 / 回读校验。
- **最快路径**：用户开 agiso 目标页 + qcqcq 货源页，并给「货源编号 + 变量名 + 档位清单（或源链接）」，我跳过扒源与爬 qcqcq，直接建 + 配 + 校验。

## 🐟 闲鱼铺货运营铁律（一条龙默认规则）

### 上游证据冲突与快速闭环（2026-11-12 用户要求固化）

- 用户明确指定上游商品介绍 / 商品图 / 购买表单等来源优先级时，按其指定来源执行；不能让接口模板或单一表单标签静默覆盖用户口径。
- 来源相互冲突：先并列核验每档详情、商品图、购买输入控件、协议模板；暂停写入/上架，向用户一次性呈现差异。用户已指定优先来源时不重复追问，按指定口径完成，并记录低优先级来源差异。
- 一条龙提速顺序：同产品线全档取数 → 先核真实成本并剔除成本 >¥20 的档 → 计算售价并筛货源余额门槛与售价 >¥150 等独立条件 → 定 SKU 和账号口径 → 快照 → 一次性配 SKU 货源与买家变量、商品级直充类型、文案主图 → 全字段回读 → 最后发布。禁止先上架后补履约配置、删档后再反复询问恢复。
- 🔴 **SKU 成本上限 ¥20（2026-11-12 用户纠正）**：限制对象是货源进价/成本，进价 >¥20 不上，正好 ¥20 可保留；售价可以超过 ¥20，但仍须 ≥ 进价并遵守其他独立上架条件。旧「售价 >¥20 不上」口径作废。 [摘要]
- 🔴 **超闸直接跳过，不要问（2026-11-15 用户定，用户原话「超过成本闸就不要上了，不用问我」）**：任一档超出成本闸（¥20）/ 货源余额门槛（≥500）/ 售价闸（¥150）时，**自行剔除该档并继续**，不要为了单件商品回来征求是否放宽阈值。**全部档都被剔除 = 这件商品不上**，在结果里说明剔除原因即可，不停下等确认。唯一例外：用户主动要求「放宽到 X 破例一次」。
- 变更旧商品时优先从完整快照恢复原 SKU ID / 价格 / 库存 / 规格；先 dry / 校验，再批量写入；写入后必须读回商品、SKU 货源、买家输入提示、商品级账号类型、图片、在售状态，不以接口“成功”响应代替验收。
- 阿奇索直充账号类型已核实：手机 `1`、剪映号 `128`、抖音号 `256`；剪映号不能误判成手机号或平台账号 `4`。对应操作 SOP：`操作-阿奇索上品一条龙.md`。

#### R1 · 直充与卡密**不得混装**

- 一件商品的所有 SKU 必须**同为直充**（`productType=1`）或**同为卡密**（`productType=2`），不允许一件里既有直充档又有卡密档。
- 需要同时卖两种形态 → **拆成两件商品**，不要塞进一个宝贝。
- 代码：`sourcing.kind_uniform_violations()`；`onepipe_guard.preflight()` 的 **①c 混装闸**（`--go` 时 fatal）；巡检项 **⑰ 类型不混装**。

#### R2 · **永远不上代充**

- 含「代充 / 代客充值 / 代下单 / 人工充值」字样的货源，**即使更便宜、即使缺货替代也一律不用**。理由：时效不可控、易纠纷、非官方渠道。
- 🔴 **接口 `productType` 区分不出代充**（人工代充也是 `1`），只能按**商品标题关键词**判定。所有判据必须走 `sourcing.is_daichong()`，不要自己写包含判断。
- 拿不到货源标题 → **不放行**（无法证明非代充即拒绝，安全闸默认拒绝）。
- 代码：`sourcing.is_daichong()` / `screen_products()`；`preflight()` 的 **①b 代充闸**；巡检项 **⑯ 无代充货源**。

#### R3 · 三家比价，**谁便宜上谁**

- 比价范围 = **志远 `95425` + 商战 `96810` + 思券 `99569`**（取代 2026-10-15「只比志远+商战」；星芒/省省/追梦/千城仍不参与）。
- **逐档比价**，同一商品不同档可以来自不同家；不按品牌整切。
- 🔴 **比价前必须先过四道否决**，否则会选到"更便宜但错"的货（三个真实坑，均已实测）：
  1. **档位不符 → 否决**。搜「哔哩哔哩大会员」时 `pno=8366`「6小时」成本 ¥0.80，比「1个月」便宜 12 元 —— 不校验档位就会把 6 小时当 1 个月卖。用 `supplier.tier_val()` + `sourcing.tier_canon()` 归一后**相等**才计入。🔴 `月卡≡1个月`、`周卡≡7天` 可等价；**`6小时 ≠ 1天`，绝不跨量纲换算**。
  2. **产品线不同 → 否决**。思券 `pno=937`「升级**超级**大会员『1个月』」¥10.05 比普会 ¥13.14 便宜 3 元，但超级大会员是另一档等级，买家会认为货不对板。修饰词（超级/升级/共享/儿童/学生/体验…）不同即不同产品线。
  3. **异常低价 → 否决+人工确认**。卡密 `pno=8276`「只支持移动手机号…链接直冲」¥1.31，同档其他货源 ¥9.42~12.46。详情写「复制发货链接到浏览器打开领取」，属限时活动/试用性质。低于同档中位数 40% 必有原因，**不许直接采用**。
- 代码：`sourcing.compare_sources(tiers, ref_title=...)` 按 档位→代充→类型→产品线→余额→异常价→取最低 的顺序判定。

#### R4 · **有账户余额限制的不上**

- 货源要求「账户余额 ≥ N 元才能下单」的档，**不上**。判据取 `limitBalance` 与描述文字（`goodsDescribe`/`notice`/`info`/`name`）中的**较大值**，阈值 `500` 元（2026-11-03 由 1000 收紧）。
- 代码：`sourcing.balance_blocked()` / `deploy.limit_balance_of()`；`deploy.filter_plan_limits()`；巡检项 **⑱ 无余额门槛**。

#### 换源前必须验买家填写项（实操铁律）

- 🔴 **比价结果不能直接采纳**：换源前必须核对新货源的 `rechargeTemplates` 能否推断出**买家填写项**（手机号/UID/QQ…）。
- 2026-11-15 实证：思券 `pno=933` 比志远 `pno=223` 便宜 ¥0.07，但思券**无参数模板**（`templates: []`），推断不出买家该填什么；志远明确是「手机号码」。**为省 7 分钱换源会导致不知道让买家填什么 → 发不出货**，故未换。
- 判据：`alds_dict.recharge_types_from_detail()` 返回 `None` 的货源，**不得用于替换一个原本判定明确的 SKU**。

### 🔴 【现行 · 2026-10-15 用户定】SKU 档位**默认全部添加**（用户原话「sku默认全部添加」）

- **上 SKU 默认把「该商品产品线内的货源全档」全部加上** —— **不必问、不必等用户说「都加」**。
- 🔴 **2026-11-15 裁决：本条原「标题随之改宽泛（覆盖全部周期），否则标题与规格不符」已作废。**
  标题档位摘要**默认只写在售最高档**，权威口径见下方「标题档位摘要默认最高档」条。
  **裁决理由**：原句把「标题档位摘要」与「规格可选档集合」混为一谈 —— 两者是不同维度，
  标题表达主推档、规格表达可选集，前者比后者窄**不构成**「标题与规格不符」。SKU 照旧全档添加，标题按最高档写。
- 🔴 **货源要求必须显式写进对应 SKU（2026-11-13 用户定）**：只要货源商品标题、介绍、图片或购买规则含「一号一次 / 同账号限兑 / 限购 / 指定账号 / 周期 / 地区」等会影响买家选择或履约的要求，就把关键条件写进对应 SKU 规格名（例如「1天·一号限一次」），并同步标题及必要的非价格性说明；不同档分别标注，不得把某档要求套到其他档。**限价信息完全不写入 SKU 规格名、商品描述或发货说明**。上架/修改后回读 SKU 名称、货源绑定和文案核验一致。此规则不替代产品线筛选与标准版选源规则。
- **边界 = 不跨产品线**。喜马拉雅实证（1092189305909）：只上「喜马拉雅VIP会员」系列 5天/7天/15天/月卡/2个月/季卡/半年卡/年卡/15个月 = 9 档；**不混**儿童会员、白金/升级白金、无用学SVIP、喜点充值、组合包、人工代充、CDK卡密、刷评类。（原「+ 首单 = 10 档」随 2026-11-09 取消首单引流款作废。）

### 🔴 【现行 · 2026-11-15 用户定】SKU 规格名必须**写清类型**，不许只写时长

- **两个必踩的坑**：① `goodsIds` 必须传**数组** `["<gid>"]`，传 `goodsId:"x"` 报「请选择需要标识为直充的商品」；② **必须带 `rechargeAccountTypes`（充值账号格式数组）**，否则报「充值账号格式至少勾选一个」。
- **验收**：`SearchGoodsList` 里 `item.setting.rechargeOnOff === true` **且** `item.apiRechargeOnOff === true`（后者才代表闲鱼官方直充**真正生效**，界面显示「使用闲鱼官方直充」），`rechargeReason` 应为「直充开通成功」。若 `rechargeOnOff=true` 但 `apiRechargeOnOff=false`，界面会提示「自动取消闲鱼官方直充…将使用聊天窗口发链接直充」= 直充没生效，需排查。
- **卡密类商品（CDK）跳过这一步**——发卡不是账号直充。
- 多数商品在配好直充 SKU alds 后已被系统自动开通，**先查后调**（已 true 就别重复调）。
- 已落地进 `alds-xianyu-sku-pipeline` 技能步骤⑩ + 项目 `一条龙服务说明.md` 第 7 节。

## 📜 历史口径（已作废，仅备查，不得执行）

> 本节集中收拢**被推翻**的旧规则。保留是为了遇到老 spec / 老记录时能认出「这是旧口径」，**不是可以拿来用**。

<details><summary>首单引流款（2026-10-12 定，2026-11-09 已废止）</summary>

- 默认自动加「首单」SKU；引流价 = 进货价 − 0.30（亏损 ≤ 0.30、无硬下限）、`ppt=1`、库存固定 10；`spec["first"]=false` 可关。

</details>

<details><summary>亏本引流款标准（2026-10-02 定，已被 10-12 取代、再被 11-09 彻底废止）</summary>

> 引流款标准 = 用户存量商品（快手币/抖音钻石）实测模式。

- 每个商品跑一条龙**必须**设一个低价引流款（命名「首单」），放在 SKU 列表最后。
- 引流款价格 = **低于成本价**（亏本引流），但**硬下限 5 元**——售价 `≥ 5 元`。
- 即 `引流价 = max(5, 成本×0.88~0.9)`；成本 < 5 元时按 5 元设。
- **命名规范**：规格维度「总量」，规格值 = `首单+面值` + 文案限购，如 `首单50快币`、`60钻石【首单特惠 限购1单】`；**「限购1单」只是规格名文案**（系统限购不存在）。

</details>

<details><summary>薄利默认 3.5%（2026-11-09 前，已被现行默认利润率取代）</summary>

- 旧口径：售价 = 进价 ÷ 0.965；自动改价区间 3.5%~4.5%。现网存量 28 商品 / 196 SKU 仍是这套价。 [摘要]

</details>

<details><summary>「售价 >¥20 不上」（2026-11-12 用户纠正，已作废）</summary>

- 旧口径把限制对象错放成「售价」；正确口径是**限制进价/成本 >¥20**，售价可以超过 ¥20。

</details>

<details><summary>档位按标题定（2026-10-14 定，已被「默认全部添加」取代）</summary>

- 标题限定了周期就只上那个周期；现改为产品线内全档默认全加。
- ⚠️ 原文后半句「标题随之改宽泛」在 **2026-11-15 再次作废**：标题档位摘要改为默认只写最高档，见上方现行条。

</details>

<details><summary>标题随之改宽泛（2026-10-15 定，已被「标题档位摘要默认最高档」取代）</summary>

- 旧口径要求标题覆盖全部在售周期，理由写的是「否则标题与规格不符」。
- **2026-11-15 用户定**：标题只写最高档。裁决理由 = 标题档位摘要与规格可选档集合是两个维度，前者窄不构成「不符」。
- 该裁决同时推翻了本条的理由本身，故不再保留「与规格不符」这一说法。

</details>
