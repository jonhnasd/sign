## 🤝 浏览器协作方式（闲鱼铺货默认，2026-09-25 确认）

**⚠️ 接口优先（2026-10-02 用户明确要求）：** 凡是能走接口/API 完成的操作，**一律优先用接口，别用 UI 自动化**。

- **背景**：闲管家 / agiso 等后台是 Vue + Element UI，UI 自动化极其脆弱——合成点击受 `isTrusted` 校验拦截、输入框只监听 `keyup.enter` 不认 `keydown`、弹窗取消/X/Esc 合成事件无效、下拉懒渲染需复用已渲染行。一次简单「加档位」要反复绕过这些坑，**投入产出比极差**。
- **因此**：能拿到官方/直连接口（如 kayixin 3.0 API、各平台 OpenAPI、页面内部 RPC）就直接调接口；**只有在确实没有接口、或接口拿不到目标字段时才退而求其次用 UI 自动化**，且 UI 自动化前先评估 ROI。
- **用户自己保持浏览器页面打开**（agiso 编辑页 + qcqcq 货源页 + 源闲鱼页），我通过 **edge-bridge 桥接 RPC** 直接调页面内部接口操作（`GetItemInfo` / `Edit` / `SaveSkuAldsInfo` 等），不依赖用户手动点击。
- 默认**不主动 `tab_new` 开页、不爬 DOM、不重启桥接**（除非标签真的掉了 / 桥接 `127.0.0.1:8787` 无监听）。用户开页 = 标签活跃 + 登录态在 = 接口零等待、不超时。
- 仍须走接口、省不掉的部分：货源成本与参数 key（qcqcq 侧取）、建 SKU / 配自动发货 / 回读校验。
- **最快路径**：用户开 agiso 目标页 + qcqcq 货源页，并给「货源编号 + 变量名 + 档位清单（或源链接）」，我跳过扒源与爬 qcqcq，直接建 + 配 + 校验。

## 🐟 闲鱼铺货运营铁律（一条龙默认规则）

### 上游证据冲突与快速闭环（2026-11-12 用户要求固化）

- 用户明确指定上游商品介绍 / 商品图 / 购买表单等来源优先级时，按其指定来源执行；不能让接口模板或单一表单标签静默覆盖用户口径。
- 来源相互冲突：先并列核验每档详情、商品图、购买输入控件、协议模板；暂停写入/上架，向用户一次性呈现差异。用户已指定优先来源时不重复追问，按指定口径完成，并记录低优先级来源差异。
- 一条龙提速顺序：同产品线全档取数 → 先核真实成本并剔除成本 >¥50 的档 → 计算售价并筛货源余额门槛与售价 >¥150 等独立条件 → 定 SKU 和账号口径 → 快照 → 一次性配 SKU 货源与买家变量、商品级直充类型、文案主图 → 全字段回读 → 最后发布。禁止先上架后补履约配置、删档后再反复询问恢复。
- 🟢 **主图幂等闸（2026-11-25 提速）**：主图已逐字核验（`whitelist_verified`）**且**输入（标题/档位/买家字段/参考图，prompt_sha256 一致）未变 → **跳过重生成**，直接复用线上图。实测本次批量 3 件因小修重跑 deploy 都白白重烧 3-5 分钟主图，加这道闸后小修重跑不再烧图。实现：`alds_kit/main_image.py` `gen_and_set_main_image`（早退前清理临时参考图/提示词文件）。
- 🟢 **快跑 key/模型列表进程内缓存（2026-11-25 提速②）**：`get_kuaipao_key()`（sops 解密）与 `list_kuaipao_models()`（`/v1/models` 网络）各只跑**一次**，批量多件复用，不再每件重复 sops 子进程 + 网络查模型。实现：`alds_kit/main_image.py` 模块级 `_KEY_CACHE` / `_MODELS_CACHE`（显式传 key 仍绕过缓存，保证可刷新）。
- 🔴 **SKU 成本上限 ¥50（2026-11-25 用户放宽，原 ¥20 为 2026-11-12 定）**：限制对象是货源进价/成本，进价 >¥50 不上，正好 ¥50 可保留；售价可以超过 ¥50，但仍须 ≥ 进价并遵守其他独立上架条件。旧「售价 >¥20 不上」口径作废。 [摘要]
- 🔴 **超闸直接跳过，不要问（2026-11-15 用户定，用户原话「超过成本闸就不要上了，不用问我」）**：任一档超出成本闸（¥50）/ 货源余额门槛（≥500）/ 售价闸（¥150）时，**自行剔除该档并继续**，不要为了单件商品回来征求是否放宽阈值。**全部档都被剔除 = 这件商品不上**，在结果里说明剔除原因即可，不停下等确认。唯一例外：用户主动要求「放宽到 X 破例一次」。

四条规则**全部已写成代码**：`tools/sourcing.py`（唯一实现）+ `tools/tests/test_sourcing_rules.py`（26 项回归锁死）。

#### R1 · 直充与卡密**不得混装**

- 一件商品的所有 SKU 必须**同为直充**（`productType=1`）或**同为卡密**（`productType=2`），不允许一件里既有直充档又有卡密档。
- 需要同时卖两种形态 → **拆成两件商品**，不要塞进一个宝贝。
- 代码：`sourcing.kind_uniform_violations()`；`onepipe_guard.preflight()` 的 **①c 混装闸**（`--go` 时 fatal）；巡检项 **⑰ 类型不混装**。

#### R2 · **永远不上代充**

- 含「代充 / 代客充值 / 代下单 / 人工充值」字样的货源，**即使更便宜、即使缺货替代也一律不用**。理由：时效不可控、易纠纷、非官方渠道。
- 🔴 **接口 `productType` 区分不出代充**（人工代充也是 `1`），只能按**商品标题关键词**判定。所有判据必须走 `sourcing.is_daichong()`，不要自己写包含判断。
- 拿不到货源标题 → **不放行**（无法证明非代充即拒绝，安全闸默认拒绝）。
- 代码：`sourcing.is_daichong()` / `screen_products()`；`preflight()` 的 **①b 代充闸**；巡检项 **⑯ 无代充货源**。

#### R3 · **志远优先**；商战 / 思券**只补稀缺档，不参与比价**

> 🔴 **2026-11-25 用户定（覆盖此前所有「逐档三家比价取低」口径）**。用户原话：「**三家货源比，一般是志远最便宜，志远没有的货源就是商战和思券了，商战和思券只负责补充稀缺货源，不负责比价**」。

- **desc 一律文案库样式（每个商品，无一例外）**：描述用 `deploy._copy_desc()` 生成（版式 = 产品名·官方直充/卡密 → 本店一句 → 填写内容 → 充值方式 → 使用说明 → 档位对照 → 三段标准条款【下单须知】/【防骗提醒】/【售后说明】 → 话题），**禁止手写**。判据（desc 必须含三段）与修法正文唯一在 [[经验-踩坑手册]] §Z⑤（§Y⑤），本处只记总则。[摘要]
- 🔴 **2026-11-25 已升级为三道机器闸强制（用户拍板 A，不再是纯约定）**：① **生成闸** `deploy.auto_copy`——spec 已给 desc 也校验三段，缺则自动 `_copy_desc` 重生成；② **发布闸** `onepipe_guard.preflight fatal`——desc 缺三段任一 → `SystemExit` 中止（不静默）；③ **回读闸** `deploy.phase_copy`——回读线上 desc 校验三段，缺则 ❌ 告警。三道全绿才放行，手写缺三段无法再静默上线。[摘要]
- **查价与其他操作一律 API 协议模式**：货源成本取阿奇索侧实时接口 `GetSupplierProductList.productCost`（`emit_spec with_cost=True` → spec 直接带 cost，deploy 优先用 `spec.cost`、**不再现场取**），售价由 `alds_dict.PRICING` / `profit_of` 分档计算；**禁止用浏览器 UI 点选、爬网页、或依赖不稳定的 v3 通道现场取价**。
- 🔴 **数据源分流（2026-11-25 用户定「按此模式，以后不浪费时间」）**：**取价**（productCost 实时）/ **货源目录** / **类型**（直充·卡密）/ **买家参数模板**（充值链接·验证码·手机号等）→ **阿奇索侧接口**（edge-bridge 127.0.0.1:8787/rpc → agiso `/api/AcprSerivces/*`）；**货源详情文字**（goodsDescribe/intro）/ **余额** → **v3（密钥协议，`v3_huafei.py`）**。**不要**浪费时间「用阿奇索侧接口取详情文字」（实测它没有 goodsDescribe/intro 字段）或「用 v3 取价」（时通时断、不稳）；详情文字取不到就让 `_copy_desc` 商品说明段留空，**不影响上品**（三段条款+档位对照照常，发布照常）。

### 🔴 一条龙必须包含「标识为直充」（2026-10-03 用户定）

- **每个商品跑一条龙，必须把商品「标识为直充」**（= 走闲鱼官方直充通道，而非发卡/聊天链接）。
- 页面：宝贝发布/商品列表页工具栏 → 勾选商品 → 「**标识为直充**」（旁为「撤销标识」）。接口 `POST /api/GoodsManage/OpenRecharge`，撤销用 `CloseRecharge`。
- **两个必踩的坑**：① `goodsIds` 必须传**数组** `["<gid>"]`，传 `goodsId:"x"` 报「请选择需要标识为直充的商品」；② **必须带 `rechargeAccountTypes`（充值账号格式数组）**，否则报「充值账号格式至少勾选一个」。
- **验收**：`SearchGoodsList` 里 `item.setting.rechargeOnOff === true` **且** `item.apiRechargeOnOff === true`（后者才代表闲鱼官方直充**真正生效**，界面显示「使用闲鱼官方直充」），`rechargeReason` 应为「直充开通成功」。若 `rechargeOnOff=true` 但 `apiRechargeOnOff=false`，界面会提示「自动取消闲鱼官方直充…将使用聊天窗口发链接直充」= 直充没生效，需排查。
- **卡密类商品（CDK）跳过这一步**——发卡不是账号直充。
- 多数商品在配好直充 SKU alds 后已被系统自动开通，**先查后调**（已 true 就别重复调）。
- 已落地进 `alds-xianyu-sku-pipeline` 技能步骤⑩ + 项目 `一条龙服务说明.md` 第 7 节。

## 📜 历史口径（已作废，仅备查，不得执行）

> 本节集中收拢**被推翻**的旧规则。保留是为了遇到老 spec / 老记录时能认出「这是旧口径」，**不是可以拿来用**。

<details><summary>首单引流款（2026-10-12 定，2026-11-09 已废止）</summary>

- 默认自动加「首单」SKU；引流价 = 进货价 − 0.30（亏损 ≤ 0.30、无硬下限）、`ppt=1`、库存固定 10；`spec["first"]=false` 可关。

</details>

<details><summary>亏本引流款标准（2026-10-02 定，已被 10-12 取代、再被 11-09 彻底废止）</summary>

> 引流款标准 = 用户存量商品（快手币/抖音钻石）实测模式。

- 每个商品跑一条龙**必须**设一个低价引流款（命名「首单」），放在 SKU 列表最后。
- 引流款价格 = **低于成本价**（亏本引流），但**硬下限 5 元**——售价 `≥ 5 元`。
- 即 `引流价 = max(5, 成本×0.88~0.9)`；成本 < 5 元时按 5 元设。
- **命名规范**：规格维度「总量」，规格值 = `首单+面值` + 文案限购，如 `首单50快币`、`60钻石【首单特惠 限购1单】`；**「限购1单」只是规格名文案**（系统限购不存在）。

</details>

<details><summary>薄利默认 3.5%（2026-11-09 前，已被现行默认利润率取代）</summary>

- 旧口径：售价 = 进价 ÷ 0.965；自动改价区间 3.5%~4.5%。现网存量 28 商品 / 196 SKU 仍是这套价。 [摘要]

</details>

<details><summary>「售价 >¥20 不上」（2026-11-12 用户纠正，已作废）</summary>

- 旧口径把限制对象错放成「售价」；正确口径是**限制进价/成本 >¥20**，售价可以超过 ¥20。

</details>

<details><summary>档位按标题定（2026-10-14 定，已被「默认全部添加」取代）</summary>

- 标题限定了周期就只上那个周期；现改为产品线内全档默认全加。
- ⚠️ 原文后半句「标题随之改宽泛」在 **2026-11-15 再次作废**：标题档位摘要改为默认只写最高档，见上方现行条。

</details>

<details><summary>标题随之改宽泛（2026-10-15 定，已被「标题档位摘要默认最高档」取代）</summary>

- 旧口径要求标题覆盖全部在售周期，理由写的是「否则标题与规格不符」。
- **2026-11-15 用户定**：标题只写最高档。裁决理由 = 标题档位摘要与规格可选档集合是两个维度，前者窄不构成「不符」。
- 该裁决同时推翻了本条的理由本身，故不再保留「与规格不符」这一说法。

</details>
